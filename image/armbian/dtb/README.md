# R36S device tree for the Armbian noble image

The R36S-Armbian noble image (kernel `6.12.32-lts-rk3326`) boots through `boot.ini`, which
loads `boot/dtb/rockchip/rk3326-gameconsole-r36s.dtb` from the rootfs and applies
`ScreenFiles/Panel N/mipi-panel.dtbo` with `fdt apply`. The kernel dtb has no `__symbols__`.
That's fine for Panels 1–4, whose overlays use `target-path`. The Panel 0 overlay uses
fixups (`gpio3`, `pcfg_pull_none`, `joypad`), though, so `fdt apply` fails, U-Boot boots
a corrupt fdt, and the kernel panics. The armbian logo then shows two garbled lines, and the
device reboots after one second (`CONFIG_PANIC_TIMEOUT=1`).

Here the panel is merged into the dtb at build time instead, and `boot.ini` loads the
merged dtb from the BOOT partition without `fdt apply`.

| Path | Contents |
|---|---|
| `base/rk3326-gameconsole-r36s.dts` | Kernel dtb decompiled; generated by `build.sh -b`, editable |
| `panels/panelN.dtsi` | Panel N amendment (`compatible`, `panel_description`), from `extract-panel.sh` |
| `boot.ini` | BOOT partition `boot.ini`: forces Panel 0, loads the merged dtb, no `fdt apply` |
| `boot-debug.ini` | Same flow, logs each U-Boot step to `BOOT/bootdebug.txt` (no UART needed) |
| `build.sh` | Builds `out/rk3326-gameconsole-r36s-merged.dtb`, optionally installs it |
| `extract-panel.sh` | `mipi-panel.dtbo` → `panels/panelN.dtsi` |

The R36S here has Panel 0 (PanCho "Original Panel"). Its init sequence and 50 MHz clock match
the working dArkOS `rk3326-r36s-panel0-linux.dtb`.

## Build and install

Requires `dtc` (`brew install dtc`, or `device-tree-compiler` on Debian/Ubuntu).

```bash
./build.sh                    # panel 0 -> out/rk3326-gameconsole-r36s-merged.dtb
./build.sh -i /Volumes/BOOT   # also copy it to "ScreenFiles/Panel 0/" and boot.ini to the card
```

## After a kernel update

The dtb in the rootfs changes but the merged one on BOOT doesn't. Regenerate the base from
the new kernel dtb and rebuild:

```bash
./build.sh -b <rootfs>/boot/dtb/rockchip/rk3326-gameconsole-r36s.dtb -i /Volumes/BOOT
```

## Another panel

```bash
./extract-panel.sh "/Volumes/BOOT/ScreenFiles/Panel 2/mipi-panel.dtbo" > panels/panel2.dtsi
./build.sh -p 2 -i /Volumes/BOOT
```

Then change the three `setenv Panel*` lines at the top of `boot.ini` to the same panel.

## Debugging a failed boot

Copy `boot-debug.ini` over the BOOT partition's `boot.ini`, boot once, and read
`bootdebug.txt` from the card; it shows which U-Boot step failed. For kernel problems, drop
`quiet` and add `panic=0` to the boot args so messages and a panic stay on screen. Put
`boot.ini` back afterwards: the debug script rewrites the FAT partition on every boot.
